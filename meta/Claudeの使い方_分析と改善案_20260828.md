# Claude の使い方 ── 分析と改善案

**分析日：** 2026年8月28日
**対象：** 本リポジトリの全9コミット（2026年8月28日 02:13〜05:00）、成果物8点、
ユーザー定義スキル3件、接続コネクタ（Gmail／Drive／Calendar／Slack／Canva／GitHub）
**結論：** 出力の質は高い。失われているのは**セッションをまたぐ記憶**であり、
事故はすべてそこから出ている。最優先は CLAUDE.md と数値台帳の設置。

---

## 1. 観測された使い方（事実）

### 1.1 セッションの形

9コミットが **2時間47分に集中**している。休憩なしの1セッションで、
資料の起こし → 批評 → 是正 → 別資料への波及 → 対外版生成 → 送付前検証 まで走り切っている。
分割されたセッションではなく、**一気通貫の長時間セッション**が基本形。

### 1.2 作業の5類型

| 類型 | 具体例 | 出力 |
| :-- | :-- | :-- |
| ① 正本化 | PDF しかない資料を編集可能な .md に全文起こし | `..._正本_v1_2.md`（373行） |
| ② 批評 | 第1.3版を第1級〜第3級に分級して10件指摘 | `v1_3_批評_20260828.md` |
| ③ 是正適用 | 是正9項目の適用、pptx の XML 直接編集17箇所 | 各コミット、`rev1.pptx` |
| ④ 派生版生成 | 内部正本 → 対外版（4変換のみ） | `ご検討資料_v1_0`、`生成手順.md` |
| ⑤ 検証 | 残存語スイープ、数値再計算、PDF体裁、メタデータ漏れ | `送付前検証記録.md` |

**Claude を「文章を書かせる相手」ではなく「資料の品質管理をさせる相手」として使っている。**
生成より、検証・是正・記録の比重が明らかに大きい。これは珍しく、かつ正しい使い方。

### 1.3 扱っている文書の網

```
事業計画書 第1.8版（マスター正本・Drive）
  ├─ 執行計画書 第1.5版
  ├─ D-Global 検討資料 ── 内部第1.5版 → 対外第1.0版（13ページPDF）
  ├─ TIB DEMO DAY デッキ（8枚 pptx + 登壇原稿）
  └─ 打診版（4ページ・NDA前）
```

5文書が **同じ数値を共有**している。158.64円/$、$74.27/kg、11,782円/kg、2.39／3.40、
92.9%、4,316kg/年、96.8%、91.4%／73.9%。1つ動かすと4文書に波及する構造。

## 2. 機能している型（維持すべきもの）

改善案の前に、**すでに正しくできていること**を確定させる。これらは崩さない。

### ① 指摘の分級に「出した時点で信用を失う」を第1級の基準に置いている
`v1_3_批評` の第1級は3件だけに絞られ、「1〜3が未了の間は対外提示不可」と
**出荷ゲート**になっている。指摘を並べるだけで終わらせていない。

### ② 誤りの非対称性で判断している
宿題16の「閾値を先に動かさない」理由：
> 2.39 を維持して実力が 1.59 なら、成立する事業から早く降りる ── 取り返せる。
> 1.59 へ下げて実力が 2.39 なら、成立しない事業に資金を注ぎ続ける ── 取り返せない。

**取り返しのつく側へ倒す**という原則が明文化されている。これは意思決定の資産。

### ③ 自分の検証手順の失敗まで記録している
送付前検証記録の「偽陰性・偽陽性（手順の記録）」4件と、そこから導いた3原則
（空白除去後の照合／数値は単位語を含めた原文照合／検索語は当該節に固有の長さ）。
**検証者が自分の検証を検証している。**

### ④ 推計を捨てず実測と並置する
§3.2 で推計 11.7 ppm を残したまま K&O 回答 10 ppm を接続。
批評自身が「推計手法自体の信頼が上がっている」と評価している通り。

### ⑤ 判断には必ず理由を書き残す
`生成手順.md` の「除去の妥当性」、宿題16の「なぜ閾値を先に動かさないか」、
SUPERSEDED ヘッダの「分岐の経緯（記録として残す）」。
**なぜそうしたかが再現できる形で残っている。**

## 3. 構造的な弱点

批評と同じ分級で述べる。

### 第1級：事故がすでに起きている

#### ① 正本の分岐 ── セッション内で二重管理が発生した

SUPERSEDED ファイルのヘッダが事故そのものを記録している。

| 時刻 | 出来事 |
| :-- | :-- |
| 02:17 | Drive へ v1.2 を転記、「以後の唯一の編集可能正本」と宣言 |
| 以後 | 是正 1・3・4・9 を**ローカルコピーにのみ**適用 |
| 〃 | 「適用済み」と報告する際に **Drive 側が古い旨を伝えなかった** |
| 結果 | Drive 由来の第1.3版に項目1・9が入らず、改訂履歴に**事実に反する記述**が入った |

批評はこれを「宣言と本文の不一致は、他の全記述の信頼を損なう」と第1級に置いた。正しい。

**これは注意不足ではなく、正本の所在を保持する仕組みが無いことによる構造的欠陥。**
再発防止として「Drive 一本化」がヘッダに書かれているが、その記述は
**廃止扱いのファイルの中にしか無い**。次のセッションの Claude は読まない。

#### ② 波及漏れが検出まで通過している

$68/kg → $74.27/kg の変更で、本文と脚注は更新され**表5行が取り残された**。
見出しは両系列が混在（51〜116 と 51〜106）。
批評で捕まったから助かったが、**変更時に波及先を列挙する仕組みが無い**ため、
同じ事故は次の単価改定でも起きる。

現に、対外第1.0版はネット単価 8,587円/kg を3箇所で使っている。
その根拠（ネット化率 72.9%）は宿題16で「一次記録に残っていない」と起票済み。
**開示の作法としては正しく処理されている** ── §4 に
「両単価の差（ネット化率 72.9%）の内訳は精査中であり、確定後に基準を統一します」と
留保が明記され、グロス／ネットの使い分けも §4・§6.4 で定義されている。

問題は開示ではなく**依存の広さ**である。72.9% が確定すると、
§4 の A（全国流失ヨウ素の総価値 年60〜86億円）と B が動く。
これは資料の入口に置かれた市場規模であり、**エグゼクティブサマリーが乗っている数値**。
根拠未確立の掛け率1つに、対外資料の最上位の主張が接続している。
その依存関係が現在どこにも一覧化されていない。

### 第2級：毎回作り直している

#### ③ 検証手順が資産化されていない

送付前検証で導いた日本語照合の3原則は、**記録ファイルの中の教訓**として存在する。
スクリプトでもスキルでもないため、次回の検証で Claude は同じ4種類の誤判定を再発させる。

同様に、対外版の「検証4層」（内部専用語／是正保持／数値再計算／PDF体裁）も、
「残存してはならない語」のリスト（日本ガス／締結済／TOEIC／カルボニル／51〜116／
0.076／72.7／¥162／2027年6月）も、**一回限りの記述**として散っている。

#### ④ プロジェクト記憶がゼロ

CLAUDE.md が存在しない。したがって毎セッション、以下をゼロから伝え直す必要がある：

- 正本はどれか（Drive の第1.8版がマスター）
- 用語規律（「売上連動報酬」→「回収量連動プロセス利用料」、「日本ガス」→「関東天然瓦斯開発」）
- NDA 稼働中で実名不可の相手先（伊勢化学、K&Oエナジー、大網白里）
- 未出願で開示不可の技術情報（応用特許①のカルボニル基、2026年10月出願予定）
- 単価は $74.27 × 158.64 の1系列のみ（$72.7・¥162 系列は削除済）
- 92.9% は仮置き値であり、使うたび留保が要る

**これらは全部すでに文書化されている。ただし Claude が起動時に読む場所には無い。**

#### ⑤ スキルが実作業と対応していない

| 定義済みスキル | 本セッションでの使用 |
| :-- | :-- |
| notes-to-onepager | 0回 |
| messy-notes-to-onepager | 0回 |
| weekly-research-digest | 0回 |

一方、実際に行った①〜⑤の5類型に対応するスキルは**1つも無い**。
作ったスキルと、実際にやっている仕事がずれている。

加えて、**`notes-to-onepager` と `messy-notes-to-onepager` はほぼ同一**である。
目的・手順6段・出力フォーマット・ルール6項・使用例（白子町7/14メモ）まで一致し、
description のトリガー文言もほぼ同じ。
どちらが起動するか不定になり、**片方だけを改良すると挙動が割れる**。

### 第3級：詰め

#### ⑥ 環境制約を作業の最後に発見している

TIB デッキ修正の17箇所を適用し終えてから、
「本サンドボックスの LibreOffice は pptx を一切変換できない」ことが判明し、
**PDF 再生成と目視 QA が未了のまま**終わっている。
さらに slide7 のテキストボックス溢れの確認をユーザーに手作業で依頼する結果になった。

環境でできること／できないことは、作業計画を立てる前に確定させるべき情報。

#### ⑦ 対外版が内部正本に自動追随しない

`生成手順.md` が正しく警告している通り、内部正本が第1.6版へ進んでも対外版は追随しない。
4変換は記録されているが、**再適用は人手**。

## 4. 改善案（優先順）

### 案1 ── CLAUDE.md を置く 〔最優先・実装30分・効果最大〕

第1級①②と第2級④を一度に潰す。第5節に**そのまま置けるドラフト**を用意した。

**効果：** 毎セッションの前提説明が不要になる。正本の所在、禁止語、用語規律、
数値の1系列統一が起動時に読まれるため、正本分岐と波及漏れが構造的に起きにくくなる。

### 案2 ── 数値台帳（`meta/数値台帳.md`）を作る 〔実装1時間・第1級②に直接効く〕

5文書が共有する数値を1枚に集約し、各値に **根拠・派生元・依存箇所・確度** を持たせる。

```
| 記号 | 値 | 単位 | 根拠 | 派生元 | 依存箇所 | 確度 |
| p_gross | 11,782 | 円/kg | $74.27 × 158.64 | Iofina 開示 | 検討資料§4,§6.3 / 計画書2.5 | 確定 |
| p_net   |  8,587 | 円/kg | p_gross × 72.9% | ★根拠不明（宿題16） | 検討資料3箇所 | 🔴要確認 |
| r       |   92.9 | %     | ── | ★根拠未確立 | M=4,316 の前提 / §1,§4,§5.5 | 🔴仮置き |
| 撤退線  |   2.39 | q×R   | 顧客フル費用の均衡点 | p_net 系 | 計画書2.5,8.2 / TIB slide7 | 据置（宿題16と13の解決待ち） |
```

**効果：** 単価を1つ動かしたとき、依存箇所の列を見れば波及先が確定する。
$68 → $74.27 の表5行取り残しは、この台帳があれば発生しない。
さらに **🔴が付いた値が対外文書に何箇所出ているか**が常時見える。

### 案3 ── 検証をスクリプト化する 〔実装2時間・第2級③〕

`tools/verify.py` として、送付前検証の4層を機械化する。日本語照合の3原則を実装に埋める。

- 空白・改行を除去してから照合（PDF 行折り返しでの偽陰性を消す）
- 数値は単位語込みで原文照合（「2億5,426万円」を「25426」で探さない）
- 検索語は節に固有の長さを確保（短語の他節ヒットを消す）
- 禁止語リストと保持必須リストを外部 YAML に置き、文書ごとに切り替える

**効果：** 検証時間が短縮され、かつ**前回の4件の誤判定が再発しない**。
実行結果をそのまま検証記録に貼れる。

### 案4 ── 実作業に対応したスキルを3本作る 〔実装2〜3時間・第2級⑤〕

| 新スキル | 内容 |
| :-- | :-- |
| `doc-critique` | 第1級（出した時点で信用を失う）／第2級（論理が通っていない）／第3級（詰め）の分級基準、良い箇所の抽出、修正順序表の出力までを型にする |
| `external-version` | 内部正本→対外版の4変換 ＋ 検証4層 ＋ 検証記録の生成 |
| `number-propagation` | 数値を1つ変更したとき、台帳の依存箇所を全走査して波及先の差分案を出す |

`doc-critique` は `v1_3_批評_20260828.md` が、`external-version` は `生成手順.md` + `送付前検証記録.md` が
**すでに完成形の見本になっている**。これらを SKILL.md へ移すだけで作れる。

### 案5 ── 重複スキルを1本に統合する 〔実装10分〕

`notes-to-onepager` と `messy-notes-to-onepager` のどちらかを削除する。
残す側の description に「議事メモ」「走り書き」「音声書き起こし」を明示してトリガーを広げる。

**効果：** 起動の不定性が消え、改良が一箇所に集まる。

### 案6 ── セッション冒頭に環境確認を入れる 〔実装15分・第3級⑥〕

CLAUDE.md に「既知の環境制約」節を置く。
現時点で確定しているのは **LibreOffice が pptx を変換できない**（原本も python-pptx 生成の
最小ファイルも同じく失敗するため、環境側の制約）。

**効果：** pptx→PDF が必要な作業は、着手前に「PDF は手元で書き出していただく」と設計できる。
17箇所を直し終えてから未了になる事態が消える。

### 案7 ── 対外版の再生成を CI 的に検知する 〔任意〕

内部正本の版数が上がったのに対外版が旧版のままなら警告する、という軽いチェック。
案3のスクリプトに1関数足すだけで実現できる。

## 6. 実施順序

| 順 | 案 | 所要 | 解消する弱点 |
| :-: | :-- | :-- | :-- |
| 1 | CLAUDE.md 設置（第5節をそのまま） | 30分 | 第1級①、第2級④ |
| 2 | 重複スキルの統合 | 10分 | 第2級⑤ |
| 3 | 数値台帳の作成 | 1時間 | 第1級② |
| 4 | 検証スクリプト化 | 2時間 | 第2級③、第3級⑥ |
