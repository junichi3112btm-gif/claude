## 3. 第1級：私が実行できない作業を10分と見積もった

### 事実

第1回分析で、案2「重複スキルの統合」を**所要10分**と見積もった。
実際にはアカウント側のスキルはこのサンドボックスから変更できず、
**加藤の手作業に依存する往復が、本セッションのユーザー入力の約2/3を占めた。**

内訳（往復の主因）：

1. 実装プロンプトの作成
2. SKILL.md の全文提示（計3回）
3. チャット欄への誤貼付（2回）── 別セッションの Claude がメモとして処理して返した
4. 設定画面の場所の確認
5. ファイル名・ファイル所在の確認
6. 削除の確認 → 置き換えの確認

**得られたのは description のトリガー2語**（「議事録おこして」「音声書き起こし」）である。
重複解消という本体は①の削除で終わっており、②の価値は小さかった。

### 原因

**提案時に「誰が実行するか」を確認しなかった。**
所要見積もりは私が実行する前提で出したが、実行主体は加藤だった。

### 加えて：私は限界を宣言してから、その限界を破る手段を見つけた

「アカウント側の状態は確認できない」と2回述べたあとで `ListSkills` を発見し、
実際には**参照できた**。**先に探すべきだった。**
検討資料の送付前検証で「自分の検査式に起因する誤判定」を記録したのと同じ型の失敗である。

### 対策（実施済み）

改善案を出すときは**「実行主体」列**を付ける。
私が実行できない項目は、所要時間ではなく**往復回数**で見積もる。

## 4. 第2級：貼り先の取り違えが3回

SKILL.md を **claude.ai のチャット欄**に貼る事故が2回、
どの画面かの問い合わせが1回。

チャット欄には `notes-to-onepager` が効いているため、
貼られた SKILL.md は「整形してほしいメモ」として処理され、
**スキル仕様書が1ページまとめに変換されて返ってきた。**
スキルとしては正常動作だが、保存はされない。

**原因：** 手順書に「編集画面（保存ボタンのある画面）」と書いたが、
**チャット欄に貼ってはいけない**とは書いていなかった。
禁止すべき経路を書かず、正しい経路だけを書いていた。

**教訓：** 手作業の手順書は、**間違えやすい経路を名指しで否定する**。
「Aへ貼る」ではなく「Aへ貼る。**Bへ貼っても保存されない**」と書く。

## 5. 第2級：本セッションで私が出した偽陽性・誤りの記録

送付前検証記録の作法にならい、自分の誤りを記録する。

| # | 内容 | 文書側 |
| :-: | :-- | :-- |
| 1 | 対外版の禁止語に「伊勢化学工業」を入れ §7 で検出 | **正しい**。NDA下の提示であり §7 は実名でなければ進捗が伝わらない |
| 2 | internal プロファイルで禁止語3件を検出 | **正しい**。いずれも本文でなくメタデータのコメント欄 |
| 3 | 「アカウント側は確認できない」と宣言 | **誤り**。`ListSkills` で参照できた |
| 4 | 機械検出の「空白地帯」「独占」を指摘に流しかけた | **正しい**。否認文と法律用語（独占的オプション権） |

**1と4は同じ原因：禁止語を文書単位で定義していた。**
正しくは「**その文書が誰にどの契約で渡るか**」ごとに定義する。
1で気づき、規律とルールに反映した結果、4は指摘として出す前に自分で潰せた。

**3は性質が違う。** 手段を探す前に限界を宣言した。**探索の不足であって判断の誤りではない。**

## 6. 良い箇所（この使い方は続ける価値がある）

### ① 規律を「説明」せず「成果物」で渡している

CLAUDE.md、CSO 検閲基準、実装プロンプトのテンプレート ── いずれも
**完成した文書を貼る**形で渡された。「こういう方針で」と説明されるより、
解釈の幅が無く、そのまま統合できる。**指示の形式として最も効率が良い。**

### ② 衝突を私に判断させ、理由の明記を要求する構造になっている

恒久執筆規律の第3層「売上連動報酬」は現行の全成果物と衝突していた。
CLAUDE.md 行動原則4（判断には理由を書き残す）があるため、
私は**採らなかった理由と差し戻し時の影響範囲を明記して保留**した。
規律が自分自身の更新にも効いている。

### ③ 分級批評が出荷判定として機能している

「第1級が未了の間は対外提示不可」という線があるため、
21件の指摘が**21件のタスクではなく4件のブロッカー**に整理される。

### ④ 不利データの開示姿勢が、検閲の武器になっている

検討資料が §2.3 で損失率30%を「応募時点の不利データ」として開示していたため、
デッキの「消耗品コスト最小」との矛盾が**検出可能になった。**
不利データを書いていなければ、この第1級は永久に見つからない。
**開示の姿勢が品質管理の資産になっている。**
