# tools

## verify.py ── 対外文書の送付前検証

2026年8月28日の送付前検証で、検査式に起因する誤判定が4件発生した（文書側はすべて正しかった）。
そこから導いた**日本語文書の機械照合の3原則**を実装している。手作業の grep より先にこれを使う。

| 原則 | 実装 | 消える誤判定 |
| :-: | :-- | :-- |
| 1 | NFKC正規化 → 空白・改行・ハイフンを除去してから照合 | PDFの行折り返しによる偽陰性 |
| 2 | 数値は単位語を含めた原文で照合（`expect: "2億5,426万円"`） | 「25426」で探して「億」で不一致 |
| 3 | 全出現箇所を区画ラベルつきで報告。短い検索語は警告 | 短語が他節を拾い、最初の一致を採る偽陽性 |

### 使い方

```bash
python3 tools/verify.py --all                                  # 完了判定（これが本命）
python3 tools/verify.py --list-profiles
python3 tools/verify.py --doc dglobal/対外版.md   --profile external --recompute
python3 tools/verify.py --doc dglobal/deck.pptx  --profile deck -v
```

終了コード 0＝合格 / 1＝不合格。

### `--all` ── 完了判定

`verify_rules.yaml` の `targets` に登録した全成果物を走査し、合否ボードを出す。

**「直した」は完了ではない。`--all` が不合格0を返したときが完了。**
`gate: true` の対外提示物が1件でも不合格なら、全体が未完了になる。
`gate: false`（廃止扱いの正本など）は参考表示で、判定に影響しない。

### 対応形式

| 形式 | 区画の単位 | 依存 |
| :-- | :-- | :-- |
| .md / .txt | 見出しごと | なし |
| .pptx | スライド＋**ノート（登壇原稿）** | なし（zip内XMLを直接読む） |
| .pdf | ページごと | `pip install pypdf` |

> pptx はノートも必ず走査する。**スライドを伏せても原稿に実名が残れば口頭で露出する。**

### ルール（`verify_rules.yaml`）

- `forbidden` ── 残存してはならない語。1件でも出れば不合格
- `required` ── 是正の維持。欠落すれば不合格
- `numbers` ── `--recompute` で算式を再計算し、単位語込みの原文と突き合わせる
- `allow_in` ── 正当な例外を認める区画（例：§13 出典の「執行計画書 第1.5版」は別文書の版）

プロファイルは `common`（全文書共通）＋各プロファイルの和で適用される。

| プロファイル | 対象 | 実名の扱い |
| :-- | :-- | :-- |
| `external` | D-Global 検討資料 対外版 | **実名は残す**（秘密保持契約に基づく提示。§7は実名でなければ進捗が伝わらない） |
| `deck` | TIB DEMO DAY デッキ | **実名は不可**（公開の場。「国内主要生産者 A社／B社」へ） |
| `internal` | 内部正本 | 内部メタデータは許容 |

数値を変更したら `meta/数値台帳.md` の依存箇所を開き、`--recompute` で再検証すること。
