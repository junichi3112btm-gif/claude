# チェックイン（Drive・メールボックスの定例確認）

## 目的

資料の「事実」は受信箱とドライブの中で動く。NDA が締結されれば文書の「未締結」が誤りになり、
正本が改訂されれば派生物が古くなる。**本作業に入る前に外の変化を取り込む。**

> 2026/08/29 の教訓：Drive のマスター正本を見ずに派生物だけで検証を完結させ、
> 顧客P/L基準の分岐（第1級）を見逃した。検出できなかったのは注意不足ではなく、
> **確認の工程そのものが無かった**ことによる。この skill はその工程を固定する。

## 手順（毎回この順で・合計2〜3分）

### 1. Gmail ── 事実状態を変えるメール

```
search_threads: newer_than:3d -in:draft
```

全件を眺めるのではなく、**文書の記載を変えうる差出人・件名**を拾う：

| 監視対象 | 到着すると変わるもの |
| :-- | :-- |
| K&O エナジー（三者間NDA修正版） | 「三者間NDA 未締結」の記載が失効 → 事実表の更新が必須 |
| 伊勢化学工業（実廃水サンプル） | 「提供に合意済・未受領」→「受領済」へ |
| JST・ツクリエ 熊谷様（D-Global） | 申請名義・推進機関の状態 |
| 千葉県・CIC 桑田様 | 定例日程・紹介案件 |
| ヨウ素学会（9/4 シンポジウム） | 未回収量 700〜1,000t の一次確認 → 「当社推計」表記を出所へ差し替え |
| 金沢工大（赤坂先生・米田様）／JSPS | BRIN 共同研究申請の状態 |
| リバネス（福岡市 Deep Tech 等）・イベント面談 | 締切・面談成立 |

### 2. Drive ── 正本と一次資料

```
list_recent_files: orderBy=lastModified
```

- **マスター正本**（事業計画書・執行計画書・検討資料）の版数・最終更新が、
  手元の認識と一致しているか。ずれていれば**先に正本を読む**。
- 新しいフォルダ・一次資料（USGS 等）が増えていれば、関係する数値の根拠に目を通す。

### 3. 報告 ── 1〜3行で

- 変化があった：何が・どの文書に効くかを1行ずつ。
- 変化なし：「チェックイン：変化なし（K&O NDA・伊勢化学サンプルとも未着）」の一言。

### 4. 変化があれば、本作業より先に反映

事実の変化は、依頼された作業より**先に**文書へ反映する（または反映が要る旨を報告して指示を仰ぐ）。
PhaseShift リポジトリでは `CLAUDE.md` §5.3 の事実表と `meta/数値台帳.md` が反映先。

## ルール

1. **本作業より先に実行する。** 古い事実の上に作業を積まない。
2. **走査結果の解釈は保守側に倒す。** 「締結されたようだ」ではなく、本文を `get_thread` で読んでから事実と扱う。
3. Gmail・Drive のコネクタが無効な環境では、その旨を1行で報告して本作業に進む（黙って省略しない）。
4. 報告は短く。定例確認が長話になると本作業を圧迫し、やがて省略される。
