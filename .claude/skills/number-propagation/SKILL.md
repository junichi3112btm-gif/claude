# 数値の波及

## 目的
数値を1つ動かしたときに、**波及先を取り残さない**。

> 2026年8月28日、$68/kg → $74.27/kg の変更で本文と脚注は更新され、**表5行が取り残された**。
> 見出しは両系列が混在した。批評で捕まったから助かったが、仕組みが無ければ再発する。
>
> 同日、顧客P/L のグロス化がデッキ slide3 へ反映されず、**旧値が23分差で取り残された**。

## 手順（毎回この順で実行）

### 1. 台帳を開く

`meta/数値台帳.md` の該当行を見つけ、**依存箇所の列**を読む。そこが波及先の全リスト。
台帳に無い数値なら、**まず台帳に行を足してから**作業を始める。

### 2. 変更の向きを判定する

| 種類 | 扱い |
| :-- | :-- |
| 根拠が確定した（🔴 → ✅） | 通常の更新 |
| 前提が変わった（単価系列の統一など） | 通常の更新。**旧系列を禁止語に登録する** |
| **閾値を緩める側へ動かす** | 🛑 **止まる。** 下記「誤りの非対称性」を適用する |

#### 誤りの非対称性（撤退ライン・閾値に適用）

厳しいまま維持して実力が上なら、成立する事業から早く降りる ── データを見て気づけるので**取り返せる**。
緩めて実力が下なら、成立しない事業に資金を注ぎ続ける ── **取り返せない**。

**したがって、緩める側へ動かすときだけ根拠を厳しく問う。**
根拠が一次記録に無い場合は動かさず、宿題として起票する。

### 3. 依存の連鎖を展開する

1つの値が別の値の派生元になっていることがある。**末端まで辿る。**

```
ネット化率 72.9% → p_net 8,587 → A（60〜86億円）→ B（29.5〜42.1億円）
r 92.9% → M 4,316 → C・D・拠点あたり増産価値 → 顧客P/L → 投資回収年数 → デッキ
```

### 4. 4箇所を必ず開く

同じ数値は1つの文書の中で**表・本文・脚注・見出し**に出る。
**表だけ／本文だけの更新は事故になる。**

### 5. 他文書を開く

| 文書 | 見るところ |
| :-- | :-- |
| 事業計画書 第1.8版（マスター） | 矛盾していないか |
| D-Global 検討資料（内部・対外） | 対外版は自動追随しない。再生成要否を判断する |
| TIB デッキ | スライド **＋ノート（登壇原稿）**。原稿の旧値は口頭で出る |
| 執行計画書 | ── |

### 6. 機械検証する

```bash
python3 tools/verify.py --doc <対象> --profile <profile> --recompute
```

旧値を `verify_rules.yaml` の **`forbidden` に、新値を `required` に登録してから**回す。
これで以後、旧値の残存が自動で検出される。

### 7. 台帳を更新する

該当行の値・算式・確度・依存箇所を書き換える。**依存箇所の列を更新し忘れない。**

## 出力フォーマット

```
# [数値名] の変更 ── 波及一覧

**変更：** [旧値] → [新値]
**根拠：** [一次資料。無ければ「根拠なし → 変更しない」]
**判定：** [実行する / 保留し宿題として起票する]

## 依存の連鎖
[図または箇条書きで末端まで]

## 波及先（全件）
| # | 文書 | 箇所 | 現在値 | 変更後 | 状態 |
| :-: | :-- | :-- | --: | --: | :-- |

## 再計算した値
[算式と検算結果]

## 機械検証
[verify.py の実行結果]

## 台帳の更新
[更新した行]

## 未了・要確認
[追えなかった内訳、確認が要る前提]
```

## ルール

1. **台帳を開かずに数値を変更しない。** 台帳に無ければ先に行を足す。
2. **表・本文・脚注・見出しの4箇所を必ず開く。**
3. **登壇原稿・スピーカーノートを必ず含める。**
4. **緩める側の変更は根拠を厳しく問う。** 根拠が無ければ動かさず起票する。
5. **旧値は禁止語に登録する。** 記憶ではなく機械で検出できる状態にする。
6. **派生値は丸めた値で計算する**（例：11,782.2 ではなく 11,782）。基準を混ぜると末端がずれる。
7. 🔴 の値を使う箇所には**必ず留保を付す**。入口の節（エグゼクティブサマリー）でも省略しない。
8. 追えなかったものは「未了・要確認」に書く。**黙って残さない。**
